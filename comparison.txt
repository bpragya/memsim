WHAT IS BEING COMPARED
======================
Two DRAM models running the same memsim core/cache front end on the same traces:

  original   = memsim's original hand-written DRAM model
               branch robaracoch-nCCDS-nCCDL-changes, results in output/
  ramulator2 = memsim with Ramulator2 as the DRAM model (DDR5_8000AN timing, DDR5_16Gb_x8)
               branch integrating-ram2, results in output_ramulator2/

Held the same on both sides:
  - Traces:          22 SPEC2017 traces, 1M instructions each (-inst_limit 1000000)
  - Address mapping: MOP4CLXOR (memsim -drammappolicy 7 / Ramulator2 addr_mapper MOP4CLXOR),
                     verified bit-for-bit identical on 200,000 addresses
  - Geometry:        2 channels x 32 banks (8 bank groups x 4), 1 rank, open page
  - Clock:           0.25 ns per cycle on both sides
  - DRAM timings:    DDR5_8000AN. The original model gets them as flags:
                     -tRC 184 -tACT 56 -tCAS 56 -tPRE 56 -tRAS 128 -tRFC 1177 -tREFI 15600 -tBUS 8
                     tCCDS/tCCDM/tCCDL = 8/16/20 (params.h defaults, same rules as Ramulator2)
  - Read latency:    data returns tCAS+tBUS = 56+8 cycles after the RD is issued on both
                     sides (Ramulator2 nCL+nBL)

What still differs is the rest of each DRAM model's internals -- see the Conclusion at
the bottom.

How to read it:
  diff       = (ramulator2 - original) / original; positive CYCLES diff = ramulator2 slower
  DRAM_ACT   = row activations; for ramulator2 = row_misses + row_conflicts, both channels
  DRAM_RBHR  = row-buffer hit rate (%); diff is in percentage points
  Traces with MPKI < 1 barely touch DRAM; they are listed but left out of the Summary.

Conclusion:
The two DRAM models now agree closely. Row-buffer behaviour matches (same MOP4CLXOR
mapping, same activations), and with CAS latency + burst added to the original model's
read path (tCAS+tBUS after the RD is issued, matching Ramulator2's nCL+nBL) the ~62
cycle/miss gap seen before is gone.

Remaining gap: bwaves (+3.2%), cactuBSSN (+3.3%) and fotonik3d (+1.4%) are still faster
in the original model. These are the most activation-heavy traces (bwaves/fotonik3d by
volume, cactuBSSN at ~1% row hit rate), which points at activation-rate limits the
original model doesn't enforce the way Ramulator2 does (nRRDS/nRRDL, nFAW=32, one
command per cycle on the command bus). Not yet tested.
