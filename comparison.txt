WHAT IS BEING COMPARED
======================
Two DRAM models running the same memsim core/cache front end on the same traces:

  original   = memsim's original hand-written DRAM model
               branch robaracoch-nCCDS-nCCDL-changes, results in output/
  ramulator2 = memsim with Ramulator2 as the DRAM model (DDR5_8000AN timing, DDR5_16Gb_x8)
               branch integrating-ram2, results in output_ramulator2/

Held the same on both sides:
  - Traces:          22 SPEC2017 traces, 1M instructions each (-inst_limit 1000000)
  - Address mapping: MOP4CLXOR (memsim -drammappolicy 7 / Ramulator2 addr_mapper MOP4CLXOR),
                     verified bit-for-bit identical on 200,000 addresses
  - Geometry:        2 channels x 32 banks (8 bank groups x 4), 1 rank, open page
  - Clock:           0.25 ns per cycle on both sides
  - DRAM timings:    DDR5_8000AN. The original model gets them as flags:
                     -tRC 184 -tACT 56 -tCAS 56 -tPRE 56 -tRAS 128 -tRFC 1177 -tREFI 15600
                     tCCDS/tCCDM/tCCDL = 8/16/20 (params.h defaults, same rules as Ramulator2)

What still differs is how each model turns those timings into request latency -- see
the Conclusion at the bottom.

How to read it:
  diff       = (ramulator2 - original) / original; positive CYCLES diff = ramulator2 slower
  DRAM_ACT   = row activations; for ramulator2 = row_misses + row_conflicts, both channels
  DRAM_RBHR  = row-buffer hit rate (%); diff is in percentage points
  Traces with MPKI < 1 barely touch DRAM; they are listed but left out of the Summary.

Summary (19 traces with MPKI>=1):
  SYS_CYCLES: original is faster than ramulator2 on every trace, by 5.8% to 24.7% (mean 15.5%)
  AVGDELAY:   ramulator2 per-miss delay is 48 to 72 cycles higher (mean 62)
  DRAM_RBHR:  within 1.62 pts on every trace (mean 0.54 pts); DRAM_ACT within 2.4% (mean 0.8%)

Conclusion:
Both simulators open and close rows the same way -- activation counts and row-buffer hit
rates match almost exactly, which confirms the MOP4CLXOR port in dram.c is bit-for-bit
equivalent to Ramulator2's mapper. The remaining gap is a near-constant ~60-70 cycles per
miss: the original model wakes the core when a read wins the data bus and never adds
CAS latency (tCAS/nCL=56) or the burst (nBL=8). Ramulator2 returns data nCL+nBL=64 cycles
after the RD command. In a scratch build that delays read completion by tCAS+8, the
original model lands within 0.9% of ramulator2 on 19 of 22 traces; the rest (bwaves,
cactuBSSN, fotonik3d -- high-bandwidth / row-conflict heavy) stay 1.3-3.2% faster,
consistent with ACT-rate limits the original model doesn't enforce (nRRDS/nRRDL, nFAW=32).
